# 5. TypeScript API Generator

The TypeScript API generator is
[`TsApiClientGenerator`](../de.jpaw.bonaparte.dsl/src/de/jpaw/bonaparte/dsl/generator/tsapi/TsApiClientGenerator.xtend).
It is enabled by `bonaparte.TypeScriptApi` (default **false**) and runs *after* the
[TypeScript model generator](04-typescript-generator.md). Where the model generator emits *types*,
this generator emits **Angular `@Injectable` API client classes** — one per logical API — that wrap
bonaparte RPC calls.

It relies on two collaborators:

- [`TsRequestClassifier`](../de.jpaw.bonaparte.dsl/src/de/jpaw/bonaparte/dsl/generator/tsapi/TsRequestClassifier.xtend)
  — decides what *kind* of request a class is and what it returns.
- [`TsNaming`](../de.jpaw.bonaparte.dsl/src/de/jpaw/bonaparte/dsl/generator/tsapi/TsNaming.xtend)
  — derives the API class name and method names.

## How it works

`doGenerate(resource, fsa)`:

1. Returns immediately unless the resource is the **current module**.
2. For every `ClassDefinition` in the current module, calls
   `TsRequestClassifier.classify(request)`. If the result is non-null and not `UNKNOWN`, it computes
   the API class name via `TsNaming.apiClassName(...)` and groups requests by
   `package.name + "|" + apiClass`.
3. For each group, writes one file at `TsModuleResolver.generatedFile(first, apiClass)` containing
   a single `@Injectable` class with one method per request.
4. If the module has an entry point, writes `api-index.ts` (the barrel that the model generator
   left as a stub).

## Request classification

`TsRequestClassifier.classify` walks the class's `extends` chain (resolving generic bindings, with a
depth limit of 16) until it finds a parent whose name matches a known **pattern**:

| Parent class name | `Pattern` |
|-------------------|-----------|
| `SearchRequest` | `SEARCH` |
| `LeanSearchRequest` | `LEAN_SEARCH` |
| `CrudSurrogateKeyRequest` | `CRUD_SURROGATE` |
| `CrudStringKeyRequest` | `CRUD_STRING` |
| `CrudCompositeKeyRequest` | `CRUD_COMPOSITE` |
| `CrudModuleCfgRequest` | `CRUD_MODULE` |
| `RefResolverRequest` | `RESOLVE` |
| `MassResolverRequest` | `RESOLVE_MANY` |
| `RequestParameters` | `SPECIAL` |
| *(anything else)* | `UNKNOWN` (no API generated) |

### Generic-argument extraction

Once the pattern is known, the classifier reads the generic arguments at pattern-specific indices:

| Pattern | ref | dto | tracking |
|---------|-----|-----|----------|
| `SEARCH` | — | index 0 | index 1 |
| `CRUD_SURROGATE` | index 0 | index 1 | index 2 |
| `CRUD_STRING` | — | index 0 | index 1 |
| `CRUD_COMPOSITE` | index 0 | index 1 | index 2 |
| `CRUD_MODULE` | (from `CrudCompositeKeyRequest` parent) | index 0 | — |
| `RESOLVE` | index 0 | — | — |

### Response pattern

The response type (from the class's `return` clause, or inherited) is classified by its ancestor:

| Response ancestor | `ResponsePattern` | Generated result type |
|-------------------|-------------------|-----------------------|
| `SearchResponse` | `SEARCH` | `DTO[]` |
| `CrudAnyKeyResponse` | `CRUD` | `DTO` |
| `RefResolverResponse` | `RESOLVE` | `number` |
| `MassResolverResponse` | `RESOLVE_MANY` | `number[]` |
| `LeanSearchResponse` | `LEAN_SEARCH` | `Description[]` |
| `ServiceResponse` (exact) | `VOID` | `void` |
| `ServiceResponse` (ancestor) | `SERVICE` | `Omit<WireType, 'returnCode'>` |
| *(none)* | `DIRECT` | the wire type |

> If a search/CRUD request does **not** have the expected response type, it is downgraded to
> `SPECIAL` (a plain method, no CRUD sugar).

## Naming rules

`TsNaming` derives names:

- **API class name** (`apiClassName`):
  - `SPECIAL` → package-based name (strip trailing `request`/`dto` segments, capitalize, append
    `Api`).
  - otherwise, if a `dtoName` exists → `stripDto(dtoName) + "Api"` (strips a trailing `DTO`).
  - otherwise → the entity name from the request name (strip `Request`, cut at the pattern marker)
    + `Api`.
- **Method name** (`methodName`): a base verb per pattern (`search`, `leanSearch`, `create`,
  `resolve`, `resolveMany`) plus a suffix from the request-name remainder after the pattern prefix.
  E.g. `CustomerSearchRequest` → `searchCustomer`.

## Generated class shape

`writeApi` emits, for a group of requests:

```ts
// autogenerated by bonaparte DSL. Do not modify, changes will be lost.

import { inject, Injectable } from '@angular/core';
import { Observable, map } from 'rxjs';
import type { BonaPortable } from '<runtime-support>';
import { RpcClient } from '<runtime-support>';
import { unwrapCrud, unwrapVoid, unwrapSearch } from '<runtime-support>';
import type { SchedulerSetupDTO, SchedulerSetupRef, ... } from '<module>';

export interface SchedulerSetupCrudRequestExtras
    extends Pick<SchedulerSetupCrudRequest, 'suppressResponseParameters'> {}

const SchedulerSetupCrudRequestPQON = "t9t.ssm.request.SchedulerSetupCrudRequest";

@Injectable({ providedIn: 'root' })
export class SchedulerSetupApi {
    private readonly rpc = inject(RpcClient);

    execute(params: Omit<SchedulerSetupCrudRequest, '@PQON' | 'suppressResponseParameters'>
            & { offset?: number } & SchedulerSetupCrudRequestExtras): Observable<SchedulerSetupDTO> {
        return this.rpc.call<...>(SchedulerSetupCrudRequestPQON, params)
            .pipe(map(unwrapCrud));
    }

    // CRUD sugar (CRUD_SURROGATE / CRUD_STRING / CRUD_COMPOSITE / CRUD_MODULE):
    create(data, extras): Observable<SchedulerSetupDTO>;   // crud: 'C'
    read(key, extras): Observable<SchedulerSetupDTO>;      // crud: 'R'
    update(key, data: Partial<DTO>, extras): Observable<SchedulerSetupDTO>;  // crud: 'U'
    delete(key, extras): Observable<void>;                 // crud: 'D'

    // CRUD_SURROGATE additionally:
    readByNaturalKey(naturalKey, extras);
    updateByNaturalKey(naturalKey, data, extras);
    deleteByNaturalKey(naturalKey, extras);

    // SEARCH:
    search(params: Omit<SchedulerSetupSearchRequest, '@PQON' | 'offset' | 'suppressResponseParameters'>
            & { offset?: number } & SchedulerSetupSearchRequestExtras): Observable<SchedulerSetupDTO[]>;
}
```

Key details:

- **Extras interfaces** — for CRUD/paging requests that have named optional fields, an
  `XExtras extends Pick<X, 'fields'>` interface is emitted so callers can pass them explicitly.
- **PQON constants** — one `const <Request>PQON = "pkg.Request"` per request, used as the RPC
  target.
- **CRUD sugar** — for the CRUD patterns, `create`/`read`/`update`/`delete` are generated with
  `crud: 'C'/'R'/'U'/'D'` and `onlyActive: false`. `CRUD_SURROGATE` additionally gets
  `readByNaturalKey`/`updateByNaturalKey`/`deleteByNaturalKey`.
- **Unwrap helpers** — each method pipes through the appropriate `unwrap*` function for its
  response pattern.

## `api-index.ts`

`writeApiIndex` produces the module's `api-index.ts` barrel. For each group it exports the API
class and any extras interfaces. Export names are made unique: on a collision the name is
qualified with the package (e.g. `T9tBaseCrudApi`), and if still colliding, suffixed `2`, `3`, …
